# CogentAI 청약 통계·SQL 진단 (부동산원)

부동산원 청약 통계 업무 지식(reb-subscription)이 든 설치에서만 쓴다. 다른 고객사는 SQL 진단만 있는 일반판 `cogentai-database` 를 쓴다.

이 스킬은 MCP 서버 `cogentai-database-reb` 의 도구를 언제, 어떻게 쓰는지 정한다.

- `mcp__cogentai_database_reb__ask_subscription_statistics`: 부동산원 청약 통계 질문에 SQL 로 답한다.
- `mcp__cogentai_database_reb__diagnose_sql`: 느린 SQL 의 실행 계획을 진단하고 튜닝 방법을 제시한다.

CogentAI 가 SQL 작성·검사·재요청을 직접 한다. 이 스킬은 SQL 을 직접 쓰거나 고치지 않는다.

## 1. 먼저 연결을 확인한다

- `mcp__cogentai_database_reb__` 도구가 없으면 CogentAI 가 연결되지 않은 것이다. 이렇게 안내한다:
  「AAS 의 내 AI 에이전트 > 프로파일 > 도구 탭 > 새 MCP 서버 > 카탈로그에서 cogentai-database-reb(CogentAI 청약 통계·SQL 진단)를 고르고, 관리자에게 받은 MCP 주소(…/mcp)와 키를 넣으세요. 넣은 뒤 「새 대화」로 다시 물어 주세요.」
- 키를 대화에 붙여 넣으라고 하지 않는다. 사용자가 키를 대화에 붙여 넣으면 쓰지 말고, 관리자에게 키를 바꿔 달라고 하라고 안내한다.
- `manage_connections`·`setup_mcp` 를 부르지 않는다. CogentAI 는 이미 연결된 MCP 서버다.

## 2. 도구를 부르는 방법

- `mcp__cogentai_database_reb__` 도구는 처음에 목록에 없다(지연 등록). `tool_describe` 로 불러온 뒤 **`tool_call` 로 부른다.** 이름으로 직접 부르면 「does not exist」로 실패한다(OKE 2026-11-08 확인).
- `tool_call` 의 `calls` 는 JSON 배열로 넘긴다(`[{"name": …, "arguments": {…}}]`). 문자열로 만들어 넣지 않는다. SQL 의 따옴표·`%` 를 JSON 문자열 안에 넣다가 이스케이프가 깨져 「`calls` is not valid JSON」 으로 실패한 적이 있다. `execute_code`·`terminal` 로 감싸서 부르지 않는다.
- 한 질문에 도구는 한 번 부른다. 결과가 왔으면 같은 인자로 다시 부르지 않는다. 다시 부르는 경우는 6절의 시간 초과뿐이다.

## 3. 청약 통계 질문

- 청약 경쟁률·공급세대수·신청건수·당첨자·미달·분양가·단지 수·공고 수를 물으면 `ask_subscription_statistics` 를 부른다. 「2025년 시도별 공급세대수」처럼 「청약」이라는 낱말이 없어도 같다.
- 「요즘 청약 분위기 어때?」처럼 넓거나 모호한 청약 질문도 **웹 검색보다 먼저** 이 도구로 묻는다. 도구가 답할 수 있는 질문 후보를 돌려주면 4절대로 고르게 한다.
- 아파트 매매가격·실거래가·시세·전월세처럼 이 데이터에 없을 수 있는 부동산 수치 질문도 **웹 검색보다 먼저** 이 도구로 묻는다. 도구가 답할 수 없다고 하면 아래 2·3번대로 한다. 웹에서 찾은 수치로 대신 답하지 않는다(OKE 2026-11-08: 「2025년 서울 아파트 매매가격 평균」에 스킬을 쓰지 않고 웹 검색 수치로 답했다).
- 웹 검색은 사용자가 뉴스·기사·웹을 찾아 달라고 할 때만 쓴다. 웹에서 찾은 수치를 부동산원 통계처럼 쓰지 않고, 쓸 때는 출처(기사 제목·주소)를 붙인다.
- `question` 에는 **사용자가 쓴 질문을 그대로** 넣는다. 낱말을 바꾸거나, 조건을 더하거나, 여러 질문으로 나누지 않는다. CogentAI 가 질문의 낱말로 조건을 고른다.
- 결과를 받으면 아래 셋 중 하나다.
  - **검증용 DB 결과도 정상 답이다.** 「검증용 DB에서 EXPLAIN·실행 성공, 결과 N행(합성 데이터라 값은 표시하지 않음) · 추정 스키마로 검사」는 오류가 아니다. 운영 DB 가 아직 연결되지 않아 합성 데이터로 SQL 을 검사했다는 뜻이다. 이때도 아래 1번대로 **SQL·적용한 조건·검사를 그대로 보인다.** 연결을 확인하려고 `diagnose_sql` 이나 다른 도구를 부르지 않는다. 값을 보고 싶어 하면 7절대로 낸다.
  1. **답(SQL·결과 표·차트)**: 답에는 SQL, `## 결과` 표(검증용 DB 면 합성 데이터 표시 포함), `## 차트` 의 ```` ```echarts ```` 블록이 **이미 다 들어 있다.** 결과의 Markdown 을 **첫 줄부터 끝까지 그대로** 붙인다. `export_subscription_result`·차트 도구·`execute_code` 를 더 부르지 않는다. 그림(PNG)을 그리지 않는다.
     AAS 에서는 결과 대신 「[AAS] 이 도구의 답(SQL·결과 표·차트)은 사용자에게 원문 그대로 이미 보인다」 안내가 온다. 답이 화면에 원문으로 이미 붙었다는 뜻이다. 같은 턴에 표·SQL·차트를 다시 쓰지 말고, 필요하면 한두 줄만 덧붙인다(이어진 질문에서 앞 표의 값을 골라 말하는 것은 아래 「앞 결과에 대한 이어진 질문」대로 한다). 사용자가 엑셀을 원하면 대화 기록에 남은 그 답의 SQL 을 7절대로 넘긴다. 절 제목·목록·표·문장을 다시 쓰거나, 표로 바꾸거나, 요약하지 않는다(「계산 방법」 목록을 표로 바꾸다가 나눗셈 방향을 「공급÷신청」으로 틀린 적이 있다. 경쟁률은 신청÷공급이다). 표의 숫자를 다시 계산하거나 반올림하지 않는다. ```` ```echarts ```` 블록이 있으면 그대로 둔다. 덧붙일 말은 결과 뒤에 한두 줄만 쓰고, 결과에 없는 수치를 지어내지 않는다.
  2. **질문 후보**(`structuredContent.candidates` 가 있다): 사용자의 질문이 모호하거나 데이터로 답할 수 없다는 뜻이다. **이때 다음 동작은 `clarify` 호출 하나다.** 답 글을 먼저 쓰지 않고, 4절대로 곧바로 `clarify` 를 부른다. 데이터 밖이라는 설명은 `clarify` 의 `question`(도구가 준 `ask`)과 선택지가 대신한다.
     - 결과 글의 「이렇게 물으면 답할 수 있습니다」 번호 목록을 글로 옮겨 적지 않는다. 그 목록은 `candidates` 와 같은 내용이고, 글로 쓰면 사용자가 눌러 고를 수 없다(OKE 2026-11-08 「2025년 청약 당첨자의 계약률과 계약 포기 비율을 시도별로 보여줘」에서 후보를 글로 옮겨 선택 카드가 뜨지 않았다).
     - 「관심 있으신 항목이 있다면 말씀해 주세요」처럼 글로 되묻지 않는다. 되묻는 것은 `clarify` 가 한다.
  3. **데이터 밖 안내**(후보 없이 답할 수 없다는 문장): 그 문장을 그대로 전한다. 다른 출처로 답을 지어내지 않는다.

- **앞 결과에 대한 이어진 질문**: 「이 중에서 경쟁률이 가장 높은 단지는?」「두 번째 단지의 공급세대수는?」처럼 바로 앞 답의 결과 표 안에서 답이 나오는 질문은 **도구를 다시 부르지 않는다.** 대화 기록에 남은 앞 답의 `## 결과` 표에서 해당 행·값을 그대로 옮겨 한두 문장으로 답한다. 값은 표에 있는 그대로 쓰고 다시 계산하거나 반올림하지 않는다. 표 전체나 SQL 을 다시 쓰지 않는다.
  - 앞 결과가 합성 데이터여도 같다. 운영 DB 가 연결되지 않은 환경이라 다시 조회해도 같은 합성 값이 나온다. 답 끝에 「합성 데이터(시험용, 실제 청약 통계가 아님) 기준입니다」를 한 줄 붙인다.
  - 표에 없는 조건(다른 연도·지역·지표)이 필요하면 새 질문이다. 사용자가 쓴 이어진 질문을 그대로 `question` 에 넣어 부른다. 앞 질문 문장을 다시 넣지 않는다.
  - 사용자가 「다시 조회해 줘」처럼 다시 조회를 직접 부탁할 때만 같은 질문으로 다시 부른다.

## 4. 후보가 오면 clarify 로 고르게 한다

- `clarify` 도구를 이렇게 부른다: `questions=[{question: <structuredContent.ask>, choices: <candidates[].question 을 순서대로>}]`.
  - `question` 은 `ask` 문자열을 **그대로** 쓴다. 「어떤 항목을 보고 싶으신가요?」처럼 바꿔 쓰지 않는다.
  - 후보는 4개까지 온다. 순서를 바꾸지 않는다. 첫 후보가 가장 가까운 질문이다(clarify 가 첫 선택지에 추천 표시를 붙인다).
  - 후보 문장을 고치지 않는다. 고친 문장은 다시 후보가 될 수 있다.
- 사용자가 후보를 고르면, **고른 질문 문장 그대로** `ask_subscription_statistics` 를 다시 부른다.
- 사용자가 「기타」로 직접 쓰면, 쓴 문장을 그대로 넘긴다.
- 오피스 대화방처럼 clarify 가 대화 글로 바뀌어 다음 발화로 답이 오면, 그 발화가 고른 질문이다. 번호(「2번」)로 답하면 그 번호의 후보 문장을 넘긴다.
- 같은 질문에 후보가 두 번 연속 오면, 세 번째로 묻지 않는다. 「이 데이터로 답할 수 있는 질문의 예」로 후보를 보이고 멈춘다.

## 5. SQL 튜닝

- 사용자가 느린 SQL 을 주고 원인이나 튜닝을 물으면 `diagnose_sql` 을 부른다.
  - `sql` 에는 사용자가 준 SQL 원문을 그대로 넣는다. 바인드 변수·주석을 지우지 않는다.
  - `connection_id` 는 사용자가 DB 를 말했을 때만 넣는다. 사용자가 DB 를 별칭(예: 「청약 검증 DB」, 「운영 DB」)으로 말하면 그 말을 `connection_id` 에 그대로 넣는다. 도구가 별칭을 연결로 바꾼다(대소문자·공백 무시). 모르면 넣지 않고 부른다. 이 키로 쓸 수 있는 연결이 하나면 도구가 그 연결로 실행 계획·통계를 직접 읽는다. 사용자에게 실행 계획이나 통계를 먼저 달라고 하지 않는다.
  - 「어느 DB 에서 느린 SQL 인지 connection_id 로 지정해 주세요. 쓸 수 있는 연결: …」이 오면, 그 연결 이름(괄호 안은 별칭)을 선택지로 `clarify` 에 「어느 DB 에서 느린가요?」를 묻고 고른 연결로 다시 부른다. 연결 목록을 지어내지 않는다.
  - 답 언어는 `lang` 에 `ko` 또는 `en` 으로 넣는다.
- 결과의 진단 Markdown(실행 계획·인덱스·통계·권고)을 첫 줄부터 그대로 보인다. 다시 쓰거나 요약하지 않는다.
- **권고를 실행하지 않는다.** 인덱스 생성·통계 수집·힌트 적용·DDL 은 사람이 검토하고 실행한다. 사용자가 실행을 부탁하면 그렇게 안내한다.
- 사용자가 준 SQL 이 쓰기 문장(INSERT·UPDATE·DELETE·DDL)이면 진단만 하고, 실행 결과를 말하지 않는다.

## 6. 시간과 오류

- 도구는 2~3분 안에 끝난다. 「시간 초과」가 오면 한 번만 다시 부른다. 두 번째도 시간 초과면 잠시 뒤 다시 물어 달라고 안내한다.
- 401·403 이 오면 키가 틀렸거나 바뀐 것이다. 카탈로그에서 키를 다시 넣으라고 안내한다.
- 「허용하지 않은 연결」이 오면 그 DB 는 이 키로 쓸 수 없다. 관리자에게 연결 허용을 요청하라고 안내한다.

## 7. 결과 값 보기·차트·엑셀 (`export_subscription_result`)

통계 답에 결과 표와 차트가 이미 있으므로, 이 도구는 주로 **엑셀**을 낼 때 쓴다. 사용자가 엑셀로 받거나, 다른 차트 종류로 다시 그려 달라고 하면 `mcp__cogentai_database_reb__export_subscription_result` 를 **`sql` 없이** 부른다. 도구가 이 대화의 마지막 통계 답 SQL 을 쓴다. SQL 을 옮겨 적거나 고치거나 새로 쓰지 않는다.

- **값 보기(`format=table`)**: 앞 50행 표가 온다. 표와 그 위의 안내 줄을 고치지 않고 붙인다.
- **다른 차트**: 사용자가 다른 종류(파이·선 등)나 일부(「상위 5개만」)를 원하면 `mcp__cogentai_database_reb__export_subscription_result` 를 `sql` 없이 `format=chart` 로 부른다. `chart_type`(bar·line·pie·area·funnel), `sort_by`(정렬할 결과 열 이름), `order`(desc 기본·asc), `limit`(남길 행 수), `value`(값 열), `category`(이름 열), `title` 을 준다. 예: 「공급세대수가 많은 상위 5개 단지를 파이 차트로」 → `chart_type=pie`, `sort_by=공급세대수(전체)`, `limit=5`, `value=공급세대수(전체)`, `category=주택명`. DB 가 전체 행에서 정렬해 고르고 차트가 원문으로 붙는다. 같은 값이 여럿이면 `then_by`(두 번째 정렬 열, 기본은 `category` 열 오름차순)로 가르므로 결과가 매번 같다. 사용자가 동점 기준을 말하면(「같으면 단지명 순」) `then_by`·`then_order` 로 넘긴다. 행을 직접 골라 차트 도구에 넘기지 않는다(표에서 직접 고르다 4위를 빠뜨렸고, 큰 표를 옮기다 JSON 이 깨졌다). 열 이름이 틀리면 도구가 쓸 수 있는 열을 알려 준다. `sql` 은 비워 둔다. 비우면 도구가 이 대화의 마지막 통계 답 SQL 을 쓴다. SQL 을 옮겨 적거나 고치지 않는다(고친 SQL 은 도구가 거절한다). 앞 답에 없는 행(예: 앞 답이 상위 3곳인데 5곳을 그려 달라)이 필요하면 먼저 `ask_subscription_statistics` 에 새 질문(「2025년 청약경쟁률 상위 5개 시도」)을 하고, `sql` 을 비운 채 다시 부른다.
- **엑셀(`format=xlsx`)**: 결과에 「[MCP resource saved to <경로> …]」가 온다. 그 파일을 작업공간으로 복사한다: `mkdir -p /opt/data/workspace/exports && cp <경로> /opt/data/workspace/exports/<파일 이름>.xlsx`. 파일 이름은 결과 첫 줄의 「엑셀 파일 <이름>」을 쓴다. 답에는 경로를 백틱으로 적는다(예: `` `/opt/data/workspace/exports/청약통계-20261107-213000.xlsx` ``). 화면이 이 경로를 내려받기 링크로 바꾼다.
- **합성 데이터 표시**: 결과에 「합성 데이터(시험용, 실제 청약 통계가 아님)」가 있으면 표·차트 제목·답 첫 줄에 그대로 남긴다. 지우거나 실제 통계처럼 쓰지 않는다. 운영 DB 결과에는 이 표시가 없다.
- 행 상한은 화면 50행, 엑셀 1만 행이다. 잘렸다는 안내가 오면 그대로 전한다.
