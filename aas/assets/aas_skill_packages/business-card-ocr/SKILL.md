# 명함 등록 → 명함 목록(CSV) → 엑셀

> `<스킬폴더>` 는 이 스킬을 불러올 때(`skill_view`) 받은 `skill_dir` 경로다(스킬 허브로 설치하면 프로파일마다 다르다). 스크립트가 종료 코드 6 으로 끝나거나 `kordoc`·`pandoc` 같은 명령이 없다(command not found)고 나오면 다시 시도하지 말고, 이 에이전트에 필요한 도구가 없다고 사용자에게 알린다.

## 꼭 지킬 것 (먼저 읽는다)

0. 「연락처로 등록해 줘」「연락처로 저장해 줘」「명함 등록해 줘」는 명함 목록에 넣으라는 뜻이다 — `cards.py add` 로 넣는다. vCard(.vcf)·주소록 파일은 사용자가 그 파일을 달라고 할 때만 만든다. 손으로 써 준 쪽지도 같다.
1. 글자는 `cards.py ocr`(kordoc)로만 읽는다. `vision_analyze` 같은 그림 분석 도구, `web_search`·`web_extract`·브라우저 도구(`browser_*`)를 쓰지 않는다. 그림 분석 도구는 느리고(시간 초과가 잦다) 글자를 바꿔 옮긴다.
2. 읽기는 두 번까지다: 기본 한 번, `--server` 한 번. 그 뒤에도 이름·전화·이메일 중 둘 이상이 원문에 없으면 **등록하기 전에** 사용자에게 묻는다(아래 「읽기」). 그림 전처리·다른 명령으로 다시 시도하지 않는다. `cards.py ocr` 결과 JSON 에 `next` 가 있으면 그 말대로만 한다.
3. 칸 값은 OCR 원문의 글자를 그대로 옮긴다. 어느 칸인지 모르는 줄(우편번호·사업자번호 등)은 `memo` 에 둔다.

## 언제 쓰나

- 사용자가 명함 사진을 올리고 「명함 등록해 줘」「연락처로 저장해 줘」「명함 정리해 줘」라고 할 때.
- 명함 대신 손으로 써 준 연락처 쪽지를 올리고 「연락처로 등록해 줘」라고 할 때(vCard 파일이 아니라 이 명함 목록에 넣는다).
- 「명함 목록 엑셀로 줘」「이번 달 받은 명함 엑셀로」라고 할 때.
- 「A사 사람 몇 명이야」「홍길동 전화번호 찾아 줘」처럼 등록한 명함을 찾을 때.
- 명함이 아닌 그림의 글자 읽기는 `ocr-to-markdown` 을 쓴다.

## 파일 위치 (AAS)

- **입력:** 메시지 끝의 `[사용자가 파일을 올렸습니다: … 경로: /opt/data/workspace/uploads/<날짜>/<이름>]` 줄의 절대 경로를 그대로 쓴다.
- **명함 목록:** 프로파일마다 하나다 — `/opt/data/workspace/business-cards/<프로파일>/cards.csv`(`cards.py` 가 `HERMES_HOME` 으로 프로파일을 가린다, 루트 프로파일은 `default`). 다른 프로파일의 목록은 보지도 고치지도 않는다. 이 스킬의 `cards.py` 만 이 파일을 고친다.
- **엑셀:** `cards.py export` 가 `/opt/data/workspace/output/명함-YYYYMMDD-HHMM.xlsx` 를 만든다. 그래야 답 아래에 내려받기 칩이 붙는다.
- **작업 파일:** `cards.py new-tmp` 가 찍어 준 폴더(`/opt/data/workspace/.tmp/cards/<시각>-<무작위>/`, 아래 `<T>`)에 둔다. 등록이 끝나면 `cards.py` 가 지운다.

스크립트: `python <스킬폴더>/scripts/cards.py` (아래에서는 `cards.py`)

## 등록하는 법

명함 한 장(앞뒷면이면 두 그림)마다 이 순서를 지킨다.

```bash
T=$(python <스킬폴더>/scripts/cards.py new-tmp)
python <스킬폴더>/scripts/cards.py ocr "<앞면 그림>" "$T/front.md"
python <스킬폴더>/scripts/cards.py ocr "<뒷면 그림>" "$T/back.md"    # 뒷면이 있을 때만
```

1. **읽기:** `cards.py ocr` 가 kordoc 으로 그림을 읽는다. 기울어진 사진이면 명함 테두리를 찾아 바로 편 그림도 읽고, 글자가 더 많이 읽힌 쪽을 남긴다(결과 JSON 의 `used` 가 `original`·`straightened`). kordoc 은 기울기를 스스로 바로잡지 않는다.
   - 읽은 줄이 적거나 이름·전화가 안 보이면 `--server` 를 붙여 한 번 더 읽는다(kordoc `--ocr-det server`, 느리지만 작은 글자를 더 찾는다).
   - 그림을 직접 보고 글자를 옮겨 적지 않는다 — 원문은 kordoc 결과다. `vision_analyze` 같은 그림 분석 도구를 쓰지 않는다.
   - **읽기는 두 번까지다.** 기본으로 한 번, `--server` 로 한 번 읽은 뒤에도 이름·전화·이메일 중 둘 이상이 원문에 없으면 더 시도하지 않는다(그림 전처리, 다른 OCR 명령, 다른 도구 모두 하지 않는다). 그때는 바로 사용자에게 알린다:
     - 원문에 읽힌 칸이 있으면 「읽힌 칸: …. 이것만 등록할까요, 아니면 명함을 똑바로 놓고 정면에서 다시 찍어 주실래요?」라고 묻는다.
     - 읽힌 칸이 거의 없으면 「글자를 읽지 못했습니다. 명함을 똑바로 놓고 정면에서 다시 찍어 주세요」라고 부탁한다.
   - kordoc 은 한국어·영어·숫자를 읽는다. **한자·중국어·일본어 명함은 거의 읽지 못한다**(한자 이름, 대만·중국·일본 명함, 세로쓰기). 이런 명함은 위 규칙대로 읽힌 칸만 등록할지 묻는다. 사용자가 값을 알려 주면 그 값을 넣는다(원문에 없으므로 `needs_review` 가 붙는 것이 맞다).
   - **한국어 손글씨**(손으로 쓴 쪽지, 명함에 손으로 덧쓴 번호)는 `--handwriting` 을 붙여 읽는다(kordoc `--ocr-rec handwriting`). 사용자가 손글씨라고 했거나, 첫 읽기 원문에 손으로 쓴 칸이 빠졌을 때 두 번째 읽기로 쓴다(이때는 `--server` 대신). 인쇄 글자뿐인 명함에는 쓰지 않는다 — 띄어쓰기·기호를 잃는다. 중국어·한자 손글씨는 이 모드로도 못 읽고 뜻 없는 한글이 나온다.
2. **칸 나누기:** `front.md`(·`back.md`)의 줄을 아래 「칸」 표의 키에 담는다. 줄의 글자를 바꾸지 않고 옮기기만 한다.
   - 「T」「Tel」「전화」는 `phone`, 「M」「Mobile」「휴대폰」은 `mobile`, 「F」「Fax」는 `fax`, 「E」「Email」은 `email`.
   - 머리 글자 없이 번호가 하나뿐이고 `010` 으로 시작하면 `mobile` 이다.
   - **이름 칸에는 이름만** 넣는다. 「오솔길 변호사」「김하늘 책임연구원」처럼 한 줄에 이름과 직함이 같이 있으면 이름은 `name`, 직함·직위는 `title` 로 나눈다(부서는 `department`). 이름이 직함으로 끝나면 `cards.py` 가 `needs_review` 로 표시한다.
   - 추측해서 빈 칸을 채우지 않는다(이메일 도메인으로 회사 이름 짓기 금지). 어느 칸인지 모르는 줄은 `memo` 에 둔다.
   - 앞뒷면은 한 JSON 으로 합친다. 영문 이름은 `name_en`. 원본 그림 경로는 `source_image` 에 `;` 로 잇는다.
3. **JSON 쓰기:** `write_file` 로 `$T/card.json` 을 쓴다. `echo`·표준 입력으로 넘기지 않는다(이름의 작은따옴표에서 명령이 깨진다). `raw_text`·`id`·`created_at`·`needs_review` 는 넣지 않는다 — 스크립트가 채운다.
4. **추가:**

   ```bash
   python <스킬폴더>/scripts/cards.py add --file "$T/card.json" --ocr "$T/front.md" [--ocr "$T/back.md"]
   ```

   스크립트가 칸 값을 OCR 원문과 대조하고 전화·이메일 형식을 본다. 원문에 없거나 형식이 맞지 않는 칸은 값을 그대로 두고 `needs_review` 에 이름을 적는다.

| 종료 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 등록됨. JSON 의 `needs_review`·`recovered` 를 본다 | 등록한 줄을 짧은 표로 보인다 |
| 2 | 입력 오류(받을 수 없는 키, 없는 id, `--ocr` 파일 없음) | 오류 문장대로 JSON·경로를 고쳐 다시 부른다 |
| 3 | 중복. 겹친 줄(`id`·이름·회사·겹친 칸)을 JSON 으로 찍는다 | 사용자에게 묻는다. 바꾸라면 `--replace <id>`, 따로 넣으라면 `--allow-duplicate` 를 붙여 다시 부른다 |
| 1 | 처리하지 못한 오류 | 「오류」로 알린다. 「명함 없음」이라고 말하지 않는다 |

- 중복은 이메일, 또는 휴대폰(`+82 10-…` 와 `010-…` 는 같은 번호), 둘 다 없으면 이름+회사로 본다. 이름+회사가 같아도 동명이인일 수 있으니 꼭 묻는다.
- `--replace <id>` 는 그 줄의 칸을 새 값으로 바꾸고 `id`·등록 시각은 둔다. OCR 원문은 앞 원문 뒤에 이어 붙이고 원본 그림 경로는 합친다(앞 사진에서 바르게 읽은 값이 계속 원문 대조를 통과한다). 바꾸기 전 목록은 `cards.csv.bak` 에 남는다.
- 같은 사람의 새 사진이면 새 JSON 에는 지금 맞다고 보는 값을 넣는다. 새 사진에서 잘못 읽힌 칸은 기존 값을 그대로 둔다.
- `recovered: true` 면 지난번 저장이 중간에 끊긴 줄이 있었다는 뜻이다. 「마지막 등록 하나가 빠졌을 수 있습니다」라고 알린다(끊긴 글자는 `cards.csv.broken` 에 있다).

## 칸

| 키 | 엑셀 머리 | 담는 것 |
|---|---|---|
| `name` | 이름 | 사람 이름만(한글이면 한글 그대로). 직함은 넣지 않는다 |
| `name_en` | 영문 이름 | 로마자 이름 |
| `company` | 회사 | 회사·기관 이름 |
| `department` | 부서 | 부서·팀 |
| `title` | 직함 | 직함·직위(이름 옆에 붙어 있어도 여기로) |
| `mobile` | 휴대폰 | 휴대폰 번호 |
| `phone` | 전화 | 사무실 전화 |
| `fax` | 팩스 | 팩스 |
| `email` | 이메일 | 이메일 |
| `address` | 주소 | 주소(여러 줄이면 줄바꿈 그대로) |
| `website` | 웹사이트 | 홈페이지 주소 |
| `memo` | 메모 | 칸을 정하지 못한 줄, 사용자가 덧붙인 말(원문 대조 안 함) |
| `source_image` | 원본 그림 | 올린 그림의 절대 경로, 앞뒷면이면 `;` 로 잇는다(원문 대조 안 함) |

## 엑셀로 내보내기

```bash
python <스킬폴더>/scripts/cards.py export [--since 2026-10-01] [--company 오픈마루]
```

- 마지막 줄에 만든 파일 경로가 나온다. 종료 코드 4 는 내보낼 명함이 없다는 뜻이다.
- 전화 칸은 글자로 들어가 앞자리 0 과 `-` 가 남는다. `needs_review` 칸은 노란색이다.
- 사용자가 목록 파일을 달라고 하면 `cards.csv` 를 주지 않고 `export` 로 만든 xlsx 를 준다. CSV 는 엑셀에서 열면 한글이 깨진다.

## 찾기

```bash
python <스킬폴더>/scripts/cards.py find "오픈마루"
```

이름·영문 이름·회사·이메일·휴대폰에서 찾는다. 결과는 `{"total": 전체 수, "rows": 최대 20줄}` 이다. 「몇 명」에는 `total` 로 답한다.

## 사용자에게 알리기

- 등록한 명함을 짧은 표(이름·회사·직함·휴대폰·이메일)로 보인다. `needs_review` 칸은 「원문과 대조가 필요합니다」라고 짚는다.
- 처음 등록할 때와 목록을 물을 때 알린다: 「명함 목록은 `business-cards/<프로파일>/cards.csv` 에 있습니다(프로파일마다 따로). 「파일」에서 이 폴더를 지우면 목록이 사라지니, 가끔 엑셀로 받아 두세요.」
- 엑셀은 경로를 적고 「답 아래 파일 칩이나 대화 메뉴의 「파일」에서 내려받을 수 있습니다」라고 안내한다. `MEDIA:` 태그나 다운로드 주소를 만들지 않는다.

## 하지 않는 것

- `cards.csv` 를 `write_file`·`patch`·셸 명령으로 직접 고치지 않는다. 반드시 `cards.py` 를 쓴다.
- 읽은 글자를 그럴듯하게 고치지 않는다(0/O, 1/l 포함). 이상한 값은 그대로 두고 확인을 부탁한다.
- 인터넷에서 모델이나 도구를 받지 않는다. `pip install`·`npm install` 을 하지 않는다(폐쇄망).
- 명함 내용을 사용자가 요청하지 않은 곳으로 보내지 않는다. 명함을 처리하는 동안 `web_search`·`web_extract`·브라우저 도구(`browser_*`)·메신저 연결·외부 MCP 를 쓰지 않는다(회사 이름·전화번호를 인터넷에서 찾아 칸을 채우지 않는다).
- 답은 사실대로 쓴다. 칸 값을 원문과 다르게 옮겼으면 「OCR 이 그렇게 읽었다」고 하지 않는다.
- 원본 그림을 고치거나 지우지 않는다. 스킬 폴더(`<스킬폴더>`)에 쓰지 않는다.
