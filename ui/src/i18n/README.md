# 화면 문구 번역 규약

화면에 보이는 문장은 코드에 직접 쓰지 않고 사전(`ko/*.ts`, `en/*.ts`)에 둔다. 한국어가 기준이고 영어는 같은 키로 짝을 이룬다.

## 쓰는 법

```ts
import { t } from '@/i18n';

t('cron.title');                       // 'Cron 작업' / 'Cron jobs'
t('cron.sub', { jobs: 3, active: 1 }); // 사전 값의 {jobs}, {active} 를 채운다
t('cron.jobs', { count: 2 });          // 영어는 cron.jobs_one / cron.jobs_other 를 고른다. 한국어는 _other 하나면 된다
```

- 컴포넌트 안에서는 `const t = useT()`(components/I18n.tsx)를 써도 되고 `@/i18n` 의 `t` 를 그대로 써도 된다. 둘은 같은 함수다.
- **`t` 는 부르는 때에 문장을 만든다.** 모듈 맨 위의 상수(배열·객체)에 번역한 문장을 얹으면 언어를 바꿔도 안 바뀐다. 상수에는 키를 두고 그리는 곳에서 `t(키)` 를 부르거나, 상수를 함수로 바꾼다.
- 언어를 바꾸면 화면 트리 전체가 다시 그려진다(components/I18n.tsx). 서버 데이터와 채팅 상태는 유지된다.
- 날짜·숫자 표기는 `localeOf()` 가 돌려주는 로캘을 쓴다(`ko-KR`, `en-US`).

## 사전 파일

- 파일 하나가 한 묶음이다. `ko/cron.ts` 와 `en/cron.ts` 처럼 **같은 이름의 쌍**을 만든다. 등록할 곳은 없고 폴더 안의 파일을 자동으로 읽는다.
- `export default { '키': '문장', ... } as Record<string, string>` 모양이다.
- 키는 `<묶음>.<뜻>` 이다. 화면의 위치가 아니라 **문장의 뜻**으로 짓는다(`cron.emptyIncidents`). 같은 문장을 여러 곳에서 쓰면 키 하나를 같이 쓴다.
- 한 묶음 파일 안의 키는 그 묶음의 접두사로만 시작한다. 여러 화면이 쓰는 공통 문장은 `common.` 이다.
- 한국어 값은 사용자가 바로 이해하는 문장으로 **다듬어 쓴다**(아래 「한국어 문구 다듬기」). 문구를 바꾸면 그 문장을 보는 시험도 새 문구로 고친다. 시험의 동작은 바꾸지 않는다.

## 검사 (i18n.test.ts, coverage.test.ts)

- 두 사전의 키가 같고 `{자리표시}` 도 같다. 영어 값에는 한글이 없다(`lang.ko` 같은 언어 이름만 예외).
- 코드(주석·정규식 제외)에 한글 문장이 남아 있으면 실패한다. 한글이 꼭 코드에 있어야 하는 줄(서버가 보내는 한글 값과 맞대어 보는 곳 등)에는 같은 줄이나 바로 윗줄에 `// i18n-ignore: <이유>` 를 단다.
- 시험·`i18n/` 폴더·`features/office/scene3d/` 는 검사하지 않는다.

## 영어 문구 규칙

- 문장은 첫 글자만 대문자(sentence case). 메뉴·단추·탭 이름은 단어 첫 글자를 대문자로 쓰지 않고 `Cron jobs` 처럼 쓴다. 제품·고유 이름(OIDC, LiteLLM, Telegram)만 대문자.
- 짧고 능동형으로. 단추는 하는 일을 쓴다(`Save changes`, `Create agent`). 오류는 사과하지 않고 무엇이 틀렸고 어떻게 고치는지 쓴다.

## 한국어 문구 다듬기

화면 문구는 번역 키로 옮기면서 사용자가 바로 이해하는 말로 고친다. 기준은 `docs-kb/WRITING_STYLE.md`(openmaru-cogentai)의 대원칙과 같다: 은유 최소화, 한자어·전문어는 일상어로, 완결된 짧은 문장, 구어체 지양, 사실부터 담백하게.

- 내부에서 쓰던 말을 화면에 그대로 내지 않는다. 사용자가 보는 것은 에이전트, 프로파일, 스킬, 크론 작업이다.
- 「에이전트」와 그 안의 「프로파일」이 한 문장에 같이 나오면 헷갈린다. 오피스에 배치하거나 담당으로 고르는 대상은 프로파일이라고 쓴다(예: 「여러 에이전트의 프로파일과 사람이 한 방에서 함께 일합니다」).
- 명사를 나열하지 말고 조사와 어미를 붙여 문장으로 쓴다. 단추와 탭 이름은 짧은 명사나 동사로 둔다(「저장」, 「에이전트 만들기」).
- 빈 화면과 오류는 무엇이 비었거나 틀렸는지, 다음에 무엇을 하면 되는지 쓴다.
- 같은 대상은 같은 말로 부른다. 같은 동작은 화면마다 같은 이름이다.

| 고쳐 쓰는 말 | 바꾼 말 | 이유 |
|---|---|---|

위 표에 없는 어색한 말도 같은 기준으로 고친다. 고친 한국어는 영어 사전의 짝도 뜻이 맞게 쓴다.

## 번역하지 않는 것

- 제품·소프트웨어 이름 중 화면 용어가 아닌 것(LiteLLM, MCP). 「Hermes」는 에이전트 안에서 돌아가는 소프트웨어 이름이라 화면에는 「에이전트」로 쓰고, 환경변수·경로·명령(`hermes`, `HERMES_HOME`)에서만 남는다.

- 서버가 보내는 문장(API 오류 메시지, 안내 문장)은 서버가 요청의 `Accept-Language` 로 만든다. `lib/api.ts` 가 화면 언어를 헤더로 보내므로 화면에서는 그대로 보인다. 서버가 한국어 값으로 고정해 보내는 배지·플래그(`꺼짐`, `실패 N회` 등)는 비교에는 그대로 쓰고 보일 때만 `serverTerm()`(`lib/serverTerms.ts`, 사전 `terms.*`)으로 바꾼다. 오류의 종류는 문장이 아니라 상태 코드나 `reason` 코드로 가린다.
- 제품 이름, 코드 식별자, 파일 경로, 환경변수 이름, 명령.
